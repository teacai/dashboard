Backup and restore

Manage the application's database and files. These actions require administrator authentication.

Backup restored successfully. The database and files have been replaced. Reload any open editors before making changes.

Download a backup

Download a ZIP containing all application data and a consistent database snapshot. Keep it in a safe place: it includes page password hashes.

Download backup

The filename is backup_yyyy_mm_dd.zip, using the server's current date.

Restore a backup

This replaces the current database and all files. Changes made since the backup will be lost. Download a fresh backup first, and only restore a trusted archive from this application.

Older backup databases are upgraded to the current schema before replacement. Backups with a newer database version are rejected. A migration or validation failure leaves the current data unchanged; if installation or database verification fails afterward, the application attempts to roll back to the previous data.

Large restores may take time. Do not close this page while the upload or restore is running. Other requests may temporarily return 503 during replacement.
